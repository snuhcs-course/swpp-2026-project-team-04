### c. What AI did well
- **Found the existing limit:** before writing code, it found that the server already cancels after 60 s from
  `match.found` (`ready_timeout`). It also found that the lobby's safety warning (up to 5 s) runs inside that window,
  so a plain 10 s from `match.found` would have left about 3–4 s for the pose. It brought this to the user as a
  decision with options.
- **Found the CI gap:** the ownership file listed `server/test/setup_timeout_test.dart`, but CI never runs
  `server/test/` (no Dart pubspec there). It put the server tests where CI runs them, the integration test file, and
  recorded why.

### d. Errors and how they were caught
- **A wrong assumption in a test:** a test expected the other player's `match.setup_state` first, but each player
  also gets their own. Caught by the first test run. Cost: one rerun.
- **Two tests that did not prove what they claimed,** both caught by mutation checks (the guard removed by hand, the
  test run again):
  - The double-tap test passed even without the close-once guard. During the page transition Flutter blocks taps, so
    the second tap never reached the button. The test now calls the button's handler twice in one frame, and it fails
    without the guard.
  - The reviewer found that no test reached the "late ready before the deadline check" branch. The `tickMs` hook
    fixed that.
- **Behavior gaps found by the reviewer** (first review: APPROVE with Minor findings):
  - The auto-ready count could hide the cancel warning.
  - Any error to `match.setup` stopped resending it for good.
- **Deploy slips, caught before any change landed:**
  - The first upload of the server sources had Windows line endings, so the install script stopped on its second
    line. Claude checked that nothing on the server had changed, then rebuilt the archive with LF endings.
  - The release build failed in the repo's Korean path. Claude built it again in an ASCII-path worktree.
  - Cost: about 20 minutes.
- **A device check that tested the wrong thing at first:** the emulator's camera permission prompt kept its setup
  camera off. The first match therefore ended by the old 60 s limit, not P12's 10 s. Claude spotted this from the
  `ready_timeout` reason, granted the permission, and ran it again.
- **Follow-up review (11-23), CHANGES_REQUESTED:**
  - The timer number set a font family inside the screen, which the design system forbids; `design_tokens_test.dart`
    does not catch it.
  - The notes still said "number only" after the user asked for a label.
  - An error left over from earlier in the match could show up as the reason the match ended.
  - All were fixed, and tests were added for the last one.
- **A timing bug that Claude and its reviewer both missed:**
  - The setup deadline and the old 60 s ready deadline were checked one after the other, and the earlier one won. A
    setup opened late (55 s) was therefore cancelled at 60 s, while the screen still showed about 5 s left.
  - The PM's independent Codex review caught it on 11-24. The tests had covered each deadline alone, never the two
    together.
  - The fix uses one rule for both deadlines. A mutation check proved the new regression tests catch the bug.
- **A new problem from fixing the second gap:** the first fix (resend after any other error) would have resent on
  every camera frame after `RATE_LIMITED`. Claude caught this while answering the follow-up review and added a 1 s
  wait, with tests.
