### Acceptance criteria → tests (P12, task.md)
- Ready just before the limit → "both ready just before the setup time ends: the match starts and is not cancelled".
- One side ready, then the limit ends → "one ready, then the setup time ends: both are told once, nobody wins or
  loses, and nothing is stored", "two apps: the setup time counts on both, its end cancels both as a setup timeout
  with no outcome, and new sessions match again".
- Rematch after the cancel → "after a setup timeout both join again and get a new match", "the setup time ran out:
  the match is cancelled with nothing recorded, and 다시 매칭 closes the screen to search again", "다시 매칭 starts
  one new search in the lobby, however often it is tapped".
- The end of a match is handled once → "one ready, then the setup time ends: …", "a ready or setup that comes after
  the deadline, before any check, cancels the match instead of starting it", "a setup sent again after the deadline
  also cancels, once".
- No loss recorded for either side → "one ready, then the setup time ends: …" (nothing stored), the two-app test
  (no outcome on both), "the setup time ran out: …" (the "승패는 기록되지 않아요" message).
- A normal battle end still goes home (PM request, 2026-11-23) → existing "a finished battle hands over to the
