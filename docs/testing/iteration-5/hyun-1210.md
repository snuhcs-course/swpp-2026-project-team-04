#### 2026-11-24 · fix after the PM's Codex review: the announced setup deadline wins over the ready deadline (P12)
- **Found by:** the PM's independent Codex review on PR #86 (CHANGES REQUESTED).
- **Problem:** if the second setup camera opened 55 s after `match.found`, the server announced a setup deadline at
  65 s, but its 60 s ready deadline still cancelled the match at 60 s as `ready_timeout`. The phones still showed about
  5 s left.
- **Fix:** `server/lib/battle_server.dart` has one rule, `_expireBeforeStart`. The ticks, `match.setup` and
  `match.ready` all use it.
  - Once both setups are open, only the announced setup deadline ends the match.
  - Until then, the 60 s ready deadline still applies, as before.
- **New tests** in the integration file (group "the setup time (P12)"). Timings are scaled: ready 1000 ms and setup
  1500 ms, or ready 300 ms and setup 2000 ms.
  - Both setups open just before the ready time ends; both ready after the ready time but before the setup deadline:
    the match starts.
  - The same case with nobody ready: `setup_timeout` at the announced deadline, exactly once, never `ready_timeout`,
    and nothing stored.
  - Until both setups are open, the ready time still ends the match as `ready_timeout`.
  - Requests with no deadline check in between follow the same rule.
- **Mutation check:** with the old unconditional `ready_timeout` check put back in the tick, both "just before the ready
  time ends" tests fail.
- **Results** (2026-11-24, on the fix merged over main `ad8a6f7`):
  - `dart analyze`: no issues.
  - The P12 group: 14 passed. It was run again after the reviewer asked for wider timing margins (ready 1500 ms,
    setup 3000 ms), and the mutation check was repeated with those margins.
  - Full `flutter test`: 3835 passed, 1 failed, 10 skipped.
  - The failure was the older test "one lost connection forfeits, two lost connections void rather than win". It got
    `finished` instead of `void` while the machine was loaded by the reviewer's parallel run. It covers the time after
    the start, which this fix does not touch, and it passed 3 times out of 3 when run alone. CI runs the full suite
    again on the pushed head.
  - Coverage: `server/lib/battle_server.dart` is outside the app's lcov. All four branches of `_expireBeforeStart` have
    tests: with a setup deadline, before and after it; without one, before and after the ready deadline.
